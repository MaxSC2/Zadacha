# CHANGE LOG — ООП Модуль 1 «Больница»

## 1. Согласование модели
- Зафиксированы 9 классов из исходной предметной области и фактического Python-кода.
- Наследование: `Person -> Patient`, `Person -> MedicalStaff`, `MedicalStaff -> Doctor`, `MedicalStaff -> Nurse`.
- Композиция: `Hospital -> Department`, `Patient -> MedicalCard`.
- Агрегация: `Department -> MedicalStaff`.
- Ассоциации: `Patient -> Appointment`, `Doctor -> Appointment`, `MedicalCard -> Appointment`.
- Dependency не используется.

## 2. Исправления исходной реализации
- `Appointment.reschedule()` теперь разрешает перенос только при статусе `запланирован`. Это устраняет повторный перенос завершённого или отменённого приёма.
- `Appointment.cancel()` теперь разрешает отмену только при статусе `запланирован`. Это устраняет повторную отмену уже завершённого/отменённого приёма.
- `Patient.issue_card(number, issue_date)` создаёт `MedicalCard` внутри `Patient`, что делает композицию отражённой не только на диаграмме, но и в коде.
- Добавлено публичное свойство `Department.location`; основной сценарий больше не обращается к `_location` напрямую.

## 3. Исправления отчёта
- Убраны из описания методы `поставитьДиагноз()` и `выписатьНазначение()`, которых нет в исходном Python.
- В таблицу атрибутов добавлен `_prescription` класса `Appointment`.
- Убрана формулировка о формальной абстрактности `Person` и `MedicalStaff`; они описаны как общие базовые классы, что соответствует фактическому Python без `abc.ABC`.
- Исправлены кратности: для отношений владения/соединения указаны значения, допустимые фактической реализацией, включая `0..*` там, где пустая коллекция допустима.
- Уточнено, что имена `_field` в Python обеспечивают внутренний доступ по соглашению, а не строгую приватность языка.
- Сценарий демонстрации приведён к фактическому `main.py`: регистрация, отделения, персонал, карта, запись, подготовка кабинета, завершение приёма, диагноз/назначения, перенос, отмена, история, поиск врачей, статистика и полиморфный `get_info()`.
