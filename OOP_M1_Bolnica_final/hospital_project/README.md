# Объектная модель «Больница» — ООП, Модуль 1

Проект реализует объектную модель учёта пациентов и медицинских приёмов,
построенную в Модуле 1. Модель полностью соответствует диаграмме классов
и листингу в отчёте: те же 9 классов и те же 10 связей четырёх типов.

**Группа ИСУ-24-1:** Бахтагареев М.Р., Добош Н. Проверила: Астапенко Н.В.

## Как запустить

Нужен Python 3.8+ (сторонние библиотеки не используются):

```bash
python main.py
```

Программа распечатает демонстрационный сценарий: создание больницы
с отделениями, закрепление персонала, запись пациента на приём,
постановку диагноза, перенос и отмену приёмов, историю обращений,
поиск врачей и статистику больницы.

## Структура проекта

| Файл | Содержимое |
|------|------------|
| `main.py` | демонстрационный сценарий работы модели |
| `hospital_model/person.py` | класс `Person` — общий родитель (ФИО, дата рождения, телефон) |
| `hospital_model/patient.py` | класс `Patient` — полис ОМС, медкарта, запись на приём |
| `hospital_model/staff.py` | классы `MedicalStaff` (абстрактный), `Doctor`, `Nurse` |
| `hospital_model/hospital.py` | классы `Hospital`, `Department` |
| `hospital_model/medical_card.py` | класс `MedicalCard` — записи о приёмах |
| `hospital_model/appointment.py` | класс `Appointment` — приём, статусы, диагноз |

## Соответствие диаграмме классов

| Связь на диаграмме | Тип | Где в коде |
|--------------------|-----|------------|
| Человек → Пациент, Человек → Медперсонал | обобщение | `Person` — родительский класс, наследование через `super()` |
| Медперсонал → Врач, Медперсонал → Медсестра | обобщение | переопределение `get_info()` (полиморфизм) |
| Больница — Отделение (1 — 1..*) | композиция | `Hospital.add_department()`: отделение создаётся внутри больницы |
| Пациент — Медкарта (1 — 1) | композиция | `Patient.issue_card()`: карта одна и хранится в пациенте |
| Отделение — Персонал (1 — 2..*) | агрегация | `Department.attach_staff()`: объекты приходят извне |
| Пациент — Приём, Врач — Приём (1 — 0..*) | ассоциация | `Patient.make_appointment()`, `Doctor.conduct_appointment()` |
| Медкарта — Приём (1 — 0..*) | ассоциация | `Appointment.complete()` сам добавляет запись в карту |

## Инкапсуляция

Внутренние атрибуты классов помечены подчёркиванием (`_name`, `_status`)
и закрыты от прямого изменения извне. Состояние объекта меняется только
его собственными методами: статус приёма — через `reschedule()`,
`complete()`, `cancel()`; списки сотрудников и записей наружу отдаются
только для чтения (кортежи).
